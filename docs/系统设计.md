# FFmpeg 静止画面剪切器——系统设计

## 1. 文档目的

本文定义桌面端“静止画面检测 + 人工确认 + 批量删除 + MP4 导出”软件的系统级架构、模块边界、核心数据流和非功能要求，作为后续详细设计与开发迭代的上层约束。

## 2. 产品定位

软件不是全自动剪辑器，而是一个半自动审核工具。程序负责寻找疑似静止区间，用户负责确认真正需要删除的区间，从而降低误删风险。

核心用户路径：

```text
打开 MP4
  -> 获取媒体信息
  -> 自动检测静止区间
  -> 列表展示候选
  -> 点击候选跳转预览
  -> 勾选一个或多个区间
  -> 计算删除结果
  -> 导出新 MP4
```

## 3. MVP 功能范围

### 3.1 必须实现

- 单个 MP4 文件导入。
- ffprobe 获取时长、分辨率、帧率、编解码器、音轨信息。
- FFmpeg freezedetect 自动扫描。
- 统一历史区间结果池：多次方向检测、相似定位和人工区间持续保留。
- 查找批次 `SearchRun`：记录来源、锚点、方向、音频条件和原始结果数量。
- 统一筛选：来源、查找批次、时长、时间范围、方向检测音频条件、仅已勾选。
- 视频播放、暂停、时间轴拖动、精确 seek 和逐帧步进。
- 点击候选区间从真实起点预览。
- 单选、多选、全选当前筛选结果、批量删除候选、批量设为不删除。
- Unified Timeline 只显示当前筛选结果，并用颜色区分来源和待删除状态。
- 删除总时长、预计输出时长按全局已勾选结果计算，不受当前筛选影响。
- 输出路径选择。
- FFmpeg Smart Copy / Smart Render 优先，必要时精确重编码。
- 导出进度、取消、错误反馈。
- 不覆盖源文件。

### 3.2 MVP 暂不实现

- ASR、OCR、VLM 或 AI 自动判定。
- 多轨剪辑。
- 转场编辑。
- 波形编辑器。
- 黑屏/静音/重复帧综合检测。
- 批量文件处理。
- macOS / Linux 安装包。

## 5. 进程边界

### 5.1 Renderer

负责 UI、用户输入、播放器状态、区间选择和展示。Renderer 不直接访问 Node.js，不直接启动 FFmpeg。

### 5.2 Preload

通过 `contextBridge` 暴露最小权限 API，例如：

- `openVideo()`
- `analyzeVideo(path, options)`
- `exportVideo(request)`
- `cancelExport(jobId)`
- `onExportProgress(listener)`

### 5.3 Main Process

负责文件对话框、路径校验、ffprobe、FFmpeg 子进程管理、stderr 解析、导出任务生命周期。

## 6. 核心模块

### 6.1 MediaImporter

职责：

- 调用系统文件选择器。
- 限制选择 MP4。
- 校验文件存在和可读性。
- 将绝对路径交给 MediaProbe。

### 6.2 MediaProbe

调用 ffprobe，输出标准化 `MediaInfo`。

### 6.3 FreezeDetector

执行：

```bash
ffmpeg -hide_banner -i input.mp4 -vf "freezedetect=n=0.003:d=2" -an -f null -
```

监听 stderr，解析：

- `lavfi.freezedetect.freeze_start`
- `lavfi.freezedetect.freeze_duration`
- `lavfi.freezedetect.freeze_end`

输出 `FreezeInterval[]`。

### 6.4 Review Workspace

由 VideoPlayer、FreezeList、Timeline 组成。

三者联动规则：

- 点击列表区间 -> 播放器 seek 到 `max(0, start - previewLead)`。
- 点击时间轴区间 -> 选中对应列表项并 seek。
- 播放器时间变化 -> 时间轴游标同步。
- 勾选状态变化 -> 列表和时间轴同时刷新视觉状态。

### 6.5 ExportPlanner

输入用户选中的 RemoveRanges，完成：

1. 排序。
2. 合并重叠或相邻删除区间。
3. 边界裁剪到 `[0, mediaDuration]`。
4. 转换为 KeepRanges。
5. 校验至少存在一个有效 KeepRange。
6. 生成 FFmpeg filter_complex。

### 6.6 VideoExporter

负责：

- 启动 FFmpeg。
- 解析进度。
- 支持取消。
- 使用临时文件输出。
- 成功后原子重命名为目标文件。
- 失败时清理临时文件。

## 8. 检测策略

MVP 默认值：

- `noise = 0.003`
- `minDurationSec = 2.0`
- `previewLeadSec = 0.5`
- `previewTailSec = 0.5`

检测参数必须可由 UI 调整并重新分析。

对含轻微编码噪声的视频，noise 过低可能漏检；过高则可能把轻微运动误认为静止。因此 UI 将 noise 命名为“检测敏感度”，内部转换为 FFmpeg 参数。

## 9. 导出策略

### 9.1 长视频导出策略

当前导出采用三层安全降级，而不是固定整片重编码：

1. **Keyframe-aware Smart Copy**：H.264 且所有内部切点均命中关键帧时，使用 concat demuxer + stream copy，音视频都不重新编码。
2. **Frame-Accurate Smart Render**：H.264 且当前编码结构满足安全条件时，只重编码非关键帧切点到下一关键帧之间的局部前缀，其余视频 packet 直接 copy。
3. **Precise Reencode Fallback**：不支持的编码、B-frame 风险、关键帧/时间戳探测失败、DTS/PTS 异常或输出时长漂移超限时，自动回退现有 filter_complex + 全量重编码路径。

Smart Render 的音频单独处理：保留区间按 30 分钟切块，最多 4 路并行使用 AAC fast coder 精确编码到 MPEG-TS；之后通过 ffconcat 的 `outpoint + duration` 固定每块理论时长，再无损 remux 为 M4A，最后与 Smart Render 视频流做 stream-copy mux。这样避免 MP4/AAC edit-list 在多区间直接 copy 时产生非单调 DTS。

### 9.2 无音轨处理

如果 `hasAudio=false`：

- Smart Copy 直接复制 H.264 视频 packet。
- Smart Render 只处理视频切点附近的 GOP，不创建音频临时文件。
- 只有进入 Precise Reencode Fallback 时才使用原有 `trim + setpts + concat(v=1:a=0)`。

### 9.3 有音轨处理

- Smart Copy：音视频一起 stream copy。
- Smart Render：视频走“局部 GOP 重编码 + 其余 copy”，音频走独立的并行 AAC 精确重建，再无损 mux。
- Precise Reencode Fallback：继续使用 `trim/atrim + setpts/asetpts + concat` 全量重建时间轴。

### 9.4 输出与安全校验

- Smart Copy / Smart Render 最终容器：MP4。
- Smart Render 边界视频编码：libx264，尽量继承源视频 bitrate、pixel format、B-frame/timescale 特征；当前检测到 B-frame 源时为安全起见直接回退全量重编码。
- Smart Render 音频：AAC 192k，`aac_coder=fast`，30 分钟分块，最多 4 路并发。
- 全量回退：libx264 / CRF 18 / preset medium + AAC 192k。
- 任一快速路径发现 `non-monotonic DTS`、DTS out-of-order、packet corrupt、输出为空或时长漂移超限时，不交付该结果，自动回退到更保守路径。

## 11. 错误模型

统一错误码：

- `FILE_NOT_FOUND`
- `UNSUPPORTED_MEDIA`
- `FFPROBE_FAILED`
- `FREEZE_DETECTION_FAILED`
- `INVALID_RANGE`
- `NO_KEEP_RANGE`
- `OUTPUT_EXISTS`
- `EXPORT_FAILED`
- `EXPORT_CANCELLED`
- `DISK_SPACE_INSUFFICIENT`

UI 显示用户可理解的信息，同时保留技术日志用于排障。

## 12. 性能目标

以 1080p H.264 为第一阶段参考：

- 打开文件到播放器可预览：< 1 秒（本地 SSD 常规文件）。
- 检测过程不阻塞 Renderer。
- 5 分钟视频分析目标：优先 < 10 秒，实际取决于编码、分辨率和机器性能。
- 长视频导出优先走 Smart Copy / Smart Render，避免按保留时长整片 H.264 重编码。
- 真实基准 `0122.mp4`（源时长约 9:40:45，H.264/AAC，删除一个非关键帧 5.333 秒区间）输出 6.52GB，端到端约 5 分钟；理论输出 34840.000 秒，实际视频 34839.9897 秒，误差约 10ms，音视频尾部差约 24ms。
- Smart Render 音频 30 分钟分块、最多 4 路并行，导出进度按多阶段窗口实时更新。
- 内存不加载整段视频，只由播放器/FFmpeg 流式访问。

## 13. 安全与文件保护

- Renderer 不暴露任意 shell 执行。
- Main Process 参数数组方式启动 FFmpeg，避免 shell 注入。
- 输入文件只读。
- 输出先写临时文件。
- 用户若选到源文件路径，必须禁止覆盖。
- 所有时间区间在导出前再次校验。

## 17. MVP DoD

MVP 完成必须满足：

1. 用户能选择任意有效 MP4。
2. 能稳定返回静止候选列表。
3. 点击任一候选可准确跳转到对应时间上下文。
4. 可勾选任意多个区间。
5. 删除区间转换 KeepRanges 的逻辑有单元测试。
6. 有音频和无音频视频均可正确导出。
7. 导出后音画同步。
8. 原文件不被修改。
9. 导出失败不会留下伪装成成功文件的残缺结果。
10. Windows 安装包可以独立运行。
